# Sentinels — API Reference

This is the developer-facing reference for calling Sentinels' four on-chain programs. It's
generated by hand from the actual instruction handlers in `programs/*/src`, not just from
`PROGRAM_SPEC.md` — if the two ever disagree, trust this file for "how do I actually call it"
and `PROGRAM_SPEC.md` for "what are the invariants this must satisfy".

There is no REST/HTTP API here. Sentinels is a set of Solana programs — the "API" is the list
of instructions each program exposes, called via a Solana RPC using the Anchor TypeScript
client. Every call below is a transaction, costs a tiny amount of SOL for fees/rent, and is
final once confirmed.

## Programs & IDs

| Program | Purpose | Program ID |
|---|---|---|
| `config` | Admin authority, global pause, per-asset risk parameters | `HczupjcktZTYtecWhmcCYnDnRM4KJRFZ23k9oSnSygku` |
| `market` | Market lifecycle, complete-set mint/merge, redemption | `9HXZJVGL4XwvKBWELccwWfj21Rv6JcA8wGiEZepfs6on` |
| `amm` | LMSR liquidity pool: init/add/remove liquidity, swap | `rrajTt3BB1QP3avwnsfBCmjpR8EMgBSvKvDJhYHH1ip` |
| `resolution` | Reads Pyth, resolves a market outcome (permissionless keeper call) | `HsGLymsSrMZhPwjT6xGCmbubUSP4e96HjTqdqRwej9uA` |

> These IDs are the ones baked into each program via `declare_id!` and used for both localnet
> and devnet in `Anchor.toml` (`anchor deploy` keeps the ID unless the keypair in
> `target/deploy/` is regenerated). If this ever needs to change again, run `anchor keys sync`
> and update this table plus `programs/market/src/constants.rs::RESOLUTION_PROGRAM_ID` (the one
> place `resolution`'s ID is cross-referenced outside its own crate).

All token amounts (USDC, DOWN, UP, LP) use **6 decimals**, matching USDC — `1_000_000` base
units = 1.0 token. Prices/strikes use Pyth's own precision (read `expo` from the price account
at runtime — see the Resolution section, never hardcode it).

## Getting started (TypeScript client)

```ts
import * as anchor from "@coral-xyz/anchor";
import { PublicKey } from "@solana/web3.js";

const provider = anchor.AnchorProvider.env(); // reads ANCHOR_PROVIDER_URL / ANCHOR_WALLET
anchor.setProvider(provider);

// IDLs are generated into target/idl/*.json by `anchor build`.
const configProgram = anchor.workspace.Config as anchor.Program;
const marketProgram = anchor.workspace.Market as anchor.Program;
const ammProgram = anchor.workspace.Amm as anchor.Program;
const resolutionProgram = anchor.workspace.Resolution as anchor.Program;
```

Point `ANCHOR_PROVIDER_URL` at `https://api.devnet.solana.com` (or a devnet RPC provider) and
`ANCHOR_WALLET` at a funded devnet keypair to talk to devnet instead of localnet.

## PDA seeds (how to derive every account address yourself)

Every stateful account in Sentinels is a PDA — a deterministic address with no private key,
derived from a program ID + a list of seeds. You never "create" these off-chain; you compute
the address client-side and pass it into the instruction (Anchor's `init`/`seeds` constraints
create/verify it on-chain).

| Account | Program | Seeds |
|---|---|---|
| `GlobalConfig` | `config` | `["config"]` |
| `RiskConfig` | `config` | `["risk", asset_feed_id]` |
| `Market` | `market` | `["market", asset_feed_id, strike_price.to_le_bytes(), expiry_ts.to_le_bytes()]` |
| `vault_authority` | `market` | `["vault", market.key()]` |
| `AmmPool` | `amm` | `["amm", market.key()]` |
| `resolver_authority` | `resolution` | `["resolver"]` |

Example derivation in TS:

```ts
const [marketPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("market"),
    assetFeedId.toBuffer(),
    strikePrice.toArrayLike(Buffer, "le", 8), // BN, u64 little-endian
    expiryTs.toArrayLike(Buffer, "le", 8),    // BN, i64 little-endian
  ],
  marketProgram.programId
);
```

## 1. `config` program

### `initialize_config(admin: Pubkey)`

Creates the singleton `GlobalConfig`. Call this exactly once per deployment.

**Accounts**

| Name | Type | Notes |
|---|---|---|
| `payer` | Signer, mut | Pays for account rent |
| `global_config` | PDA, init | `["config"]` |
| `system_program` | Program | |

```ts
await configProgram.methods
  .initializeConfig(adminPubkey)
  .accounts({ payer: payer.publicKey, globalConfig: globalConfigPda, systemProgram: SystemProgram.programId })
  .signers([payer])
  .rpc();
```

### `set_pending_admin(new_admin: Pubkey)`

Signer must be the current `admin`. First step of the two-step admin handover (avoids locking
the protocol out via a mistyped address).

### `accept_admin()`

Signer must be `pending_admin`. Sets `admin = pending_admin`, clears `pending_admin`.

### `set_paused(paused: bool)`

Signer must be `admin`. When `true`, `market` and `amm` reject new state-changing instructions
(redemption still works — see `PROGRAM_SPEC.md`).

### `upsert_risk_config(asset_feed_id, max_staleness_secs, max_confidence_bps, trading_halt_secs, lmsr_b_min, enabled)`

Signer must be `admin`. Creates or updates the `RiskConfig` PDA for one asset.

**Accounts**: `admin` (Signer, mut), `global_config` (PDA), `risk_config` (PDA,
`init_if_needed`, `["risk", asset_feed_id]`), `system_program`.

```ts
await configProgram.methods
  .upsertRiskConfig(btcFeedId, new anchor.BN(60), 100, new anchor.BN(300), new anchor.BN(1_000_000_000), true)
  .accounts({ admin: admin.publicKey, globalConfig: globalConfigPda, riskConfig: riskConfigPda, systemProgram: SystemProgram.programId })
  .signers([admin])
  .rpc();
```

**Errors**: `InvalidRiskConfig` (bad numeric values), `Unauthorized` (wrong signer).

> ⚠️ Known debt, documented in the code (`upsert_risk_config.rs`): this takes effect
> immediately in the MVP. Per `CLAUDE.md`, a timelock is required before mainnet.

## 2. `market` program

### `create_market(asset_feed_id: Pubkey, strike_price: u64, expiry_ts: i64)`

Signer: `admin`. Creates a new market plus its `down_mint`/`up_mint`/collateral vault.

**Accounts**: `admin` (Signer, mut), `global_config` (config PDA), `risk_config` (config PDA,
must be `enabled`), `market` (PDA, init), `vault_authority` (PDA, unchecked — the mint/vault
authority), `down_mint` (init, 6 decimals, authority = `vault_authority`), `up_mint` (same),
`usdc_mint`, `collateral_token_account` (init, ATA owned by `vault_authority`),
`token_program`, `associated_token_program`, `system_program`.

**Errors**: `Unauthorized`, `ProtocolPaused`, `InvalidRiskConfig` (asset disabled),
`ExpiryTooSoon` (`expiry_ts` must be `> now + trading_halt_secs`).

```ts
await marketProgram.methods
  .createMarket(btcFeedId, strikePriceBN, expiryTsBN)
  .accounts({
    admin: admin.publicKey,
    globalConfig: globalConfigPda,
    riskConfig: riskConfigPda,
    market: marketPda,
    vaultAuthority: vaultAuthorityPda,
    downMint: downMintKeypair.publicKey,
    upMint: upMintKeypair.publicKey,
    usdcMint,
    collateralTokenAccount: collateralAta,
    tokenProgram: TOKEN_PROGRAM_ID,
    associatedTokenProgram: ASSOCIATED_TOKEN_PROGRAM_ID,
    systemProgram: SystemProgram.programId,
  })
  .signers([admin, downMintKeypair, upMintKeypair])
  .rpc();
```

### `mint_complete_set(amount: u64)`

Signer: any user. Deposits `amount` USDC, mints `amount` DOWN + `amount` UP to the caller —
one atomic transaction, so the 1:1 collateral invariant can never be broken mid-flight.

**Accounts**: `user` (Signer, mut), `global_config`, `risk_config`, `market` (mut, must be
`Active`), `vault_authority`, `down_mint` (mut), `up_mint` (mut), `collateral_token_account`
(mut), `user_usdc_account` (mut), `user_down_account` (init_if_needed ATA),
`user_up_account` (init_if_needed ATA), `token_program`, `associated_token_program`,
`system_program`.

**Errors**: `MarketNotActive`, `ProtocolPaused`, `TradingHalted` (inside the pre-expiry halt
window), `InsufficientCollateral` (not enough USDC).

```ts
await marketProgram.methods
  .mintCompleteSet(new anchor.BN(100_000_000)) // 100 USDC
  .accounts({ user: user.publicKey, globalConfig: globalConfigPda, riskConfig: riskConfigPda,
    market: marketPda, vaultAuthority: vaultAuthorityPda, downMint, upMint,
    collateralTokenAccount, userUsdcAccount, userDownAccount, userUpAccount,
    tokenProgram: TOKEN_PROGRAM_ID, associatedTokenProgram: ASSOCIATED_TOKEN_PROGRAM_ID,
    systemProgram: SystemProgram.programId })
  .signers([user])
  .rpc();
```

### `merge_complete_set(amount: u64)`

The reverse of minting, pre-resolution: burns `amount` DOWN + `amount` UP from the caller,
releases `amount` USDC back from the vault.

**Accounts**: `user`, `market` (mut, `Active`), `vault_authority`, `down_mint` (mut),
`up_mint` (mut), `collateral_token_account` (mut), `user_usdc_account` (mut),
`user_down_account` (mut), `user_up_account` (mut), `token_program`.

**Errors**: `MarketNotActive`.

### `redeem(amount: u64)`

Post-resolution: burns `amount` of the **winning** token, pays out `amount` USDC. There's no
instruction to redeem the losing side — the balance just sits, worthless.

**Accounts**: same shape as `merge_complete_set`, but `market` must be `Resolved`.

**Errors**: `MarketNotResolved`.

```ts
await marketProgram.methods
  .redeem(new anchor.BN(100_000_000))
  .accounts({ user: user.publicKey, market: marketPda, vaultAuthority: vaultAuthorityPda,
    downMint, upMint, collateralTokenAccount, userUsdcAccount, userDownAccount, userUpAccount,
    tokenProgram: TOKEN_PROGRAM_ID })
  .signers([user])
  .rpc();
```

### `apply_resolution(...)` — not user-callable

Internal-only. Can only be invoked as a Cross-Program Invocation (CPI) signed by
`resolution` program's own `resolver_authority` PDA — `market` verifies the caller is
genuinely that program before trusting the outcome it's asked to write. You never call this
directly from a client; it's what `resolution::resolve_market` calls internally.

## 3. `amm` program (LMSR pool)

### `init_pool(b: u64, fee_bps: u16)`

Signer: `admin`. Creates the pool for a market. `b` (the liquidity parameter, in the same
6-decimal units as USDC) is **locked forever** after this call.

**Accounts**: `admin`, `global_config`, `risk_config` (checks `b >= lmsr_b_min`), `market`
(must be `Active`), `amm_pool` (PDA, init), `lp_mint` (init, authority = `amm_pool`),
`down_mint`, `up_mint`, `pool_down_account` / `pool_up_account` (init ATAs owned by
`amm_pool`), `token_program`, `associated_token_program`, `system_program`.

**Errors**: `Unauthorized`, `ProtocolPaused`, `LiquidityBelowMinimum`, `MarketNotActive`.

```ts
await ammProgram.methods
  .initPool(new anchor.BN(1_000_000_000), 30) // b = 1000 tokens, fee = 0.30%
  .accounts({ admin: admin.publicKey, globalConfig: globalConfigPda, riskConfig: riskConfigPda,
    market: marketPda, ammPool: ammPoolPda, lpMint: lpMintKeypair.publicKey, downMint, upMint,
    poolDownAccount, poolUpAccount, tokenProgram: TOKEN_PROGRAM_ID,
    associatedTokenProgram: ASSOCIATED_TOKEN_PROGRAM_ID, systemProgram: SystemProgram.programId })
  .signers([admin, lpMintKeypair])
  .rpc();
```

### `add_liquidity(down_amount: u64, up_amount: u64)`

Deposits DOWN+UP (must be equal amounts in the MVP — mint a complete set first if you only
have USDC) and mints LP shares proportional to the value you contributed, valued at the
**current LMSR price** (not raw token count), so early and late LPs are treated fairly.

**Accounts**: `user`, `market` (`Active`), `amm_pool` (mut), `lp_mint` (mut), `down_mint`
(mut), `up_mint` (mut), `pool_down_account` / `pool_up_account` (mut), `user_down_account` /
`user_up_account` (mut), `user_lp_account` (init_if_needed ATA), `token_program`,
`associated_token_program`, `system_program`.

**Errors**: `MarketNotActive`, `InvalidLiquidityRatio` (unequal or zero amounts),
`EmptyPool`, `MathOverflow`.

### `remove_liquidity(lp_amount: u64)`

Burns `lp_amount` of `lp_mint`, returns a proportional share of the pool's DOWN+UP balances.
Only while `market.status == Active` — after resolution, LPs redeem through
`market::redeem` instead.

**Accounts**: `user`, `market` (`Active`), `amm_pool`, `lp_mint` (mut), `pool_down_account` /
`pool_up_account` (mut), `user_down_account` / `user_up_account` (mut), `user_lp_account`
(mut), `token_program`.

**Errors**: `MarketNotActive`, `EmptyPool`, `MathOverflow`.

### `swap(side_in: SwapSide, amount_in: u64, min_amount_out: u64)`

The core trading instruction. `side_in` is `{ down: {} }` or `{ up: {} }` on the client side
(Anchor serializes the Rust enum as a tagged object). Hands `amount_in` of `side_in` to the
pool, receives the other side back, priced by the LMSR curve, minus `fee_bps`.

**Accounts**: `user`, `global_config`, `risk_config`, `market` (`Active`), `amm_pool` (mut),
`pool_down_account` / `pool_up_account` (mut), `user_down_account` / `user_up_account` (mut),
`token_program`.

**Errors**: `TradingHalted`, `SlippageExceeded` (`amount_out < min_amount_out`),
`MathOverflow`, `LmsrMathError`.

```ts
await ammProgram.methods
  .swap({ up: {} }, new anchor.BN(50_000_000), new anchor.BN(45_000_000)) // sell 50 UP, want >= 45 DOWN back
  .accounts({ user: user.publicKey, globalConfig: globalConfigPda, riskConfig: riskConfigPda,
    market: marketPda, ammPool: ammPoolPda, poolDownAccount, poolUpAccount,
    userDownAccount, userUpAccount, tokenProgram: TOKEN_PROGRAM_ID })
  .signers([user])
  .rpc();
```

## 4. `resolution` program

### `resolve_market()`

Signer: **anyone** — this is the one deliberately permissionless instruction, meant to be
called by a keeper bot once a market has expired. Takes no explicit arguments; everything it
needs comes from the accounts passed in (notably the live Pyth `price_update` account).

**Accounts**

| Name | Type | Notes |
|---|---|---|
| `keeper` | Signer | Anyone — no special authority required |
| `risk_config` | config PDA | Read-only, provides staleness/confidence thresholds |
| `market` | mut | Must be `Active` |
| `price_update` | `PriceUpdateV2` (Pyth) | The live oracle account for this market's asset |
| `resolver_authority` | PDA (`["resolver"]`) | Signs the internal CPI into `market::apply_resolution` |
| `market_program` | Program | The `market` program, for the CPI |

**What it checks, in order (any failure reverts the whole transaction):**
1. `now >= market.expiry_ts` → else `MarketNotYetExpired`.
2. `market.status == Active` → else `MarketAlreadyResolved` (this is what makes resolution
   permanent — you cannot resolve twice).
3. `price_update.feed_id == market.asset_feed_id` → else `OracleFeedMismatch` (stops someone
   passing in the wrong asset's price account).
4. `price_update.publish_time >= now - max_staleness_secs` → else `OraclePriceStale`.
5. `price >= 0` → else `NegativeOraclePrice`.
6. `conf * 10_000 / price <= max_confidence_bps` → else `OracleConfidenceTooWide`.

**Effect**: sets `market.outcome = Down` if `price < strike_price`, else `Up`;
`market.status = Resolved`; records `resolved_price` and `resolved_at`.

```ts
// You need a fresh Pyth price update account for the target feed. On devnet, either use the
// standing sponsored account from config/pyth-feeds.json, or pull+post a fresh update via
// @pythnetwork/pyth-solana-receiver.
await resolutionProgram.methods
  .resolveMarket()
  .accounts({
    keeper: keeper.publicKey,
    riskConfig: riskConfigPda,
    market: marketPda,
    priceUpdate: btcPriceUpdateAccount, // from config/pyth-feeds.json on devnet
    resolverAuthority: resolverAuthorityPda,
    marketProgram: marketProgram.programId,
  })
  .signers([keeper])
  .rpc();
```

## Error reference (all programs)

| Program | Error | Meaning |
|---|---|---|
| config | `Unauthorized` | Signer isn't the current `admin` / `pending_admin` |
| config | `InvalidRiskConfig` | Bad numeric values passed to `upsert_risk_config` |
| market | `MarketNotActive` | Instruction requires `status == Active` |
| market | `MarketNotResolved` | `redeem` called before resolution |
| market | `TradingHalted` | Inside the pre-expiry halt window |
| market | `InsufficientCollateral` | Caller doesn't hold enough USDC to mint |
| market | `Unauthorized` | Signer isn't `admin` |
| market | `ProtocolPaused` | `GlobalConfig.paused == true` |
| market | `InvalidRiskConfig` | Asset's `RiskConfig` missing/disabled |
| market | `ExpiryTooSoon` | `expiry_ts` too close to `now` |
| market | `MathOverflow` | Checked arithmetic failed |
| market | `InvalidOutcome` | Internal — `apply_resolution` given `Unresolved` |
| amm | `MarketNotActive` | Market isn't `Active` |
| amm | `TradingHalted` | Inside the pre-expiry halt window |
| amm | `ProtocolPaused` | Protocol paused |
| amm | `Unauthorized` | Signer isn't `admin` (pool-creation only) |
| amm | `LiquidityBelowMinimum` | `b < RiskConfig.lmsr_b_min` |
| amm | `InvalidLiquidityRatio` | `add_liquidity` amounts unequal or zero |
| amm | `SlippageExceeded` | `amount_out < min_amount_out` |
| amm | `EmptyPool` | Pool has no liquidity to value against |
| amm | `MathOverflow` | Checked arithmetic failed |
| amm | `LmsrMathError` | LMSR fixed-point math failed (extreme inputs) |
| resolution | `MarketNotYetExpired` | Called before `expiry_ts` |
| resolution | `MarketAlreadyResolved` | Market isn't `Active` anymore |
| resolution | `OraclePriceStale` | Pyth `publish_time` too old |
| resolution | `OracleConfidenceTooWide` | Pyth confidence interval too wide |
| resolution | `OracleFeedMismatch` | Wrong price account for this market's asset |
| resolution | `NegativeOraclePrice` | Pyth reported a negative price |
| resolution | `MathOverflow` | Checked arithmetic failed |

## Notes for whoever integrates against this

- This file documents the four Anchor programs directly — there's no hosted SDK yet (`M6` in
  `docs/IMPLEMENTATION_PLAN.md` is still open). Until then, build against the raw IDL output
  in `target/idl/*.json` after `anchor build`, using the call shapes above.
- Every instruction above already has an Anchor test (happy path + failure paths) in
  `tests/*.ts` — those are the most reliable "worked examples" if something here is unclear.
- Once deployed to devnet, add a `[programs.devnet]` section pointer in `Anchor.toml` for
  anyone reading this — the program IDs themselves should stay the same as the table above,
  since `anchor deploy` reuses whatever keypair already exists in `target/deploy/`.
